# Contributing

Thanks for taking a look. Issues and pull requests are welcome.

## Getting set up

```bash
npm install
npm run dev     # http://localhost:5173
```

You'll want an eve agent to point it at — either one you already have, or a new
one from the Agents homepage. Sign in to Vercel from the first-run screen; that
session is what Build and the runs list read from.

## Before you write UI

**Read [AGENTS.md](AGENTS.md).** It's the design contract, and most review
comments would otherwise repeat it. The parts that catch people out:

- **Icons come from `vercel-geist-icons`.** Never hand-draw or approximate one.
  If a concept has no Geist icon, use the nearest that exists or ship none.
- **No colour literals.** Use the tokens; if none fits, add one to *both*
  `:root` blocks in `app/globals.css`.
- **Check both themes.** Light and dark, every time — the switcher is in the
  account menu.
- **Reuse the primitives.** There is one menu, one tooltip, one modal shape,
  one loader family. A second implementation of an existing control is the
  thing most likely to be sent back.

`components/ui/` is generated by shadcn and can be overwritten by a
`shadcn add` re-run. A few files there carry deliberate edits, marked with a
comment saying so — keep them if you regenerate.

## Pull requests

- Keep the change scoped to one thing.
- Say what you verified, and how. "Checked in both themes at 900px" beats
  "should be fine".
- Speed is the project's stated priority: never put a subprocess spawn, port
  scan, or network call on a polling path.

## Releases

Maintainer only, and automatic: bump the version in `package.json`, push to
`main`, and the release workflow builds the package, publishes it to npm, tags
the commit and cuts a GitHub release.
